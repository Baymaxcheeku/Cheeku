longitudestringOptional

Optional. Longitude to check for service availability. Required if no pincode given. -180 <= longitude <= 180.

List labs

Returns the labs active for your store, each with its chain and the packages it offers from your store network. type is the kind of center. A COLLECTION_CENTER is a sample-collection point that serves home sample collection and normally takes no center visits, so it does not do scans. A DIAGNOSTIC_CENTER or HOSPITAL takes center visits; which scans and other center tests it does depends on the tests it offers. Decide which services to offer at a lab from isHomeSampleSupported and isCenterVisitSupported rather than from type, and pass testIds or packageIds to checkServiceability or getSlots to find the labs that offer all of them.

Move a test order to a status (UAT only)

Available only in the UAT environment; anywhere else it answers 403. Use it to test how your integration handles each stage of an order without waiting for a lab to act on it.

Moves one of your orders forward to targetOrderStatus, one status at a time. The call answers 202 straight away with order.statusPath: every status the order will pass through, starting with its current status. The first change is made right after the response and the rest follow interval seconds apart, so in the example below the order reaches PHLEBO_STARTED about 10 seconds after the call.

The changes are real. The order keeps each new status, and every change appears in its history as it would if a lab had made it.

Update an order

Updates the identifiers you gave an existing order. Send orderId plus at least one of referenceId and uniqueId; anything you omit is left unchanged. referenceId replaces your own reference on the order, and an empty string clears it. uniqueId renames the patient this order belongs to — the patient record itself, so the new uniqueId is what every other order and appointment of theirs reports too. It is rejected with 400 if any other patient of yours already uses that uniqueId — including when the order's own patient already has it, so the same call run twice fails the second time — and with 400 when the patient on the order is not one of yours to rename. Place a request

Creates a request - an enquiry raised against the authenticated store, not an order. Use it when a customer has shown interest but the booking is not yet confirmed: the request is followed up, the details and pricing are settled, and once the order has been placed the two are tied together with Link a request to an order. Only name and mobile are required. Any packages and tests given must be part of your store network, and an optional labId pins the request to a single lab, which must support every package and test given as well as the requested orderType. If the customer has already paid your store for this request, give the amount in amountPaidToStore. The order booked from the request is then set up by default for your store to collect payment from the customer.
