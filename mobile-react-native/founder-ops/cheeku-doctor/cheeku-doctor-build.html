One case, end to end

Who calls whom, in order.

Solid arrows are calls, dashed arrows are pushes or Realtime events. Every status change goes through one database function, case_transition(), which also writes the event log.

Component 1 · Protocol engine

Ten conditions as data, compiled like the safety lexicon.

Where

src/lib/quickrx/
  protocols.yaml            ← clinical lead signs this
  protocols.generated.ts    ← pnpm quickrx:build
  engine.ts                 ← pure, sync, no network
  eligibility.ts
  engine.test.ts
  fixtures/must-refer.ts    ← frozen red-flag suite
supabase/functions/_shared/quickrx/  ← same engine, server copy

One protocol, in YAML

- id: uri_sore_throat
  version: 3
  signed_by: clinical_lead · 2027-01-08
  ask: [temp_max, days, swallow, breath,
        rash, pregnancy, chronic, age]
  refer_if:
    - days > 3
    - temp_max >= 103
    - breath == "short"
    - swallow == "cannot"
  diagnoses: [viral_uri, viral_pharyngitis,
              allergic_rhinitis, needs_exam]
  formulary: [paracetamol_650, saline_gargle,
              cetirizine_10, lozenges]

Contract

Same shape as safety/detect: pure, synchronous, under 50 ms, no I/O. Returns eligible | refer | escalate with rule ids, never text.

Runs twice

On the device for instant feedback, then again in quickrx-intake. The server's answer is the one that counts.

Frozen suite

Every red flag has a must-refer fixture in English, Hindi and Hinglish. CI fails if any one stops firing. Changes need the clinical lead's sign-off in the PR.

Component 3 · Payments

Two rails, one server truth.

A review (pass, extra)

  1. quickrx-pay creates a Razorpay order for the case
  2. App opens Razorpay's UPI intent sheet (native SDK, in the January build)
  3. payments-webhook verifies the signature and calls case_transition(paid)
  4. The app's own success callback is ignored for state; it only shows a spinner

Blocked on: Apple 3.1.3(d) and Google Play confirming a consult can be paid outside store billing. Fallback: a consumable in-app purchase, same webhook shape.

Plans and allowances

  1. Solo and Family stay on store billing; the existing tier logic in billing/ decides the allowance (2 or 5)
  2. debit_allowance() runs inside the same transaction as eligible → paid
  3. A decline, refer or expiry restores it in the same transaction
  4. The demo function activate_tier_demo and its flag are dropped first (see migration 0012 note)

Idempotency

Order id = case id. A repeated webhook is a no-op; a repeated tap reopens the same order.

Refunds

Only quickrx-tick and the ops RPC can refund, through the original rail, logged in case_events.

Money in paise

Integers everywhere, as billing/plans.ts already does. ₹49 is 4900.

Component 4 · Queue and doctor console

Claim, decide, sign. Nothing else on the screen.

Queue

  • Realtime subscription on consult_cases where status = 'queued' and city in shift.cities
  • claim_case() picks the oldest with SKIP LOCKED; one open case per doctor
  • Sound and browser notification for a new case; oldest wait shown in the header
  • Summary only until claimed: age band, sex, condition, wait

Decide

  • Diagnosis chips from the protocol; plan stays hidden until one is picked
  • Plan prefilled from the formulary for that diagnosis; edits limited to dose, days and advice within max_days and max_daily_dose
  • Approve needs a 4-digit signing PIN; review timer must pass 45 s
  • Call patient (masked), ask a question, move to video, decline with reason

Stack

A separate small web app in doctor-console/: React with Vite, supabase-js, its own Vercel project. Not part of the member app's web export.

Auth

Supabase Auth, role doctor set by ops only after registration is verified. TOTP MFA required. Session ends at shift end.

Never

No free-text drug entry. No access to past cases after closure + 24 h. No payment information.

Component 5 · Issuing the prescription

A signed PDF, a code a chemist can check.

Triggerapproved fires rx-issue through a database webhook
RenderPDF with pdf-lib in Deno: doctor name, qualification, reg. no., patient name, age, sex, date, diagnosis, generic names in capitals, dose, days, advice, mode of consult
SealSHA-256 of the PDF stored; 10-character verify code; QR to rx-verify
FilePrivate rx bucket; a prescription record in records; medicine ledger rows
CheckExisting rx-score runs the 10 checks against her other medicines; a conflict goes back to the doctor before release
Notifypush-dispatch: "Dr. Mehta has sent your prescription"

The verify page shows only: valid or not, doctor name and reg. no., date, medicine names, patient initials. No history, no diagnosis.

Component 6 · The clock, quickrx-tick

A clock that runs every minute and keeps every promise.

WhenConditionAction
+5 minQueued, unclaimedAlert backup panel (push and SMS to on-call doctors)
+10 minStill unclaimedOffer to LabStack consult overflow through partner-gateway
+30 minNo prescriptionexpired → refunded, allowance restored, apology push
Claimed +12 minNo decisionNudge the doctor; at +20 min release the claim back to the queue
Issued +24 hFollow-up duePush "How are you feeling?"; no answer by +48 h closes the case
Daily 02:00All cases closed yesterdaySample 10% into case_audits for the clinical lead

Scheduled with pg_cron calling the function through pg_net. The function is idempotent; two runs in the same minute change nothing.

Component 7 · Fulfilment

Deliver through LabStack, or hand it to any chemist.

Delivery

"Order medicines" calls partner-gateway (the LabStack plan's P0 task) with the formulary ids mapped to drugMasterId by the brand-to-salt resolver. The partner pharmacist checks the prescription before dispatch. Order lands in partner_orders.

Download

Signed URL to the PDF, valid 7 days, regenerated on demand. The QR works at any chemist without the app.

How we know it works

Tests before code reaches a doctor, metrics after.

Tests

  • Unit (vitest): protocol engine, eligibility, allowance maths, price in paise; frozen must-refer suite
  • Database (tests/db): every RLS row above, every illegal transition refused
  • Contract: Razorpay webhook fixtures, LabStack fixtures from the sandbox
  • Copy: new strings added to copy.test.ts
  • Dry run: 200 synthetic cases through real doctors on staging before any real member

Live metrics

  • Paid to claimed, p50 and p90 (target p90 under 10 min)
  • Paid to prescription, p90 under 25 min
  • Doctor approval rate per doctor (alert outside 70% to 92%)
  • Refund rate (alert over 5%), webhook failures (alert on any)
  • Refer and escalate rate by protocol
  • Check-in: better, same, worse at 48 h

Alerts go to

An ops channel and the on-call engineer. Queue over 10 minutes pages the clinical lead too.

Logs

Case id, rule ids, timings. Never answers, names or medicines, as in the safety gate.

Kill switch

quickrx_enabled = false hides the chip within a minute; open cases still finish.
